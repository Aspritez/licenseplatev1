# ผลทดลองปรับพารามิเตอร์ License plate v23

ทดลองวันที่ 16 กันยายน 2026 กับ `License plate.v23-v4-8.yolov8.zip` จำนวน 456 ภาพ และ 459 กรอบป้าย

**ผลบนชุดทดสอบดีขึ้นเพียง 1 ภาพ แต่คืนกรอบคลาดเคลื่อนมากขึ้น ตอนประเมินจึงเพิ่มเป็น preset ทดลอง ต่อมาผู้ใช้เลือกให้ “ทดลอง dataset v23” เป็นค่าเริ่มต้นของแอป โดยผลทดลองด้านล่างยังคงเดิม**

## การแบ่งข้อมูลและวิธีวัด

- ZIP มีเฉพาะ `train` ทุกภาพมีขนาด 416 × 416 และมีภาพดัดแปลง 3 ภาพต่อกลุ่มต้นฉบับ รวม 152 กลุ่ม
- รวมกลุ่มด้วยชื่อไฟล์ก่อน `.rf.` แล้วสุ่มด้วย seed 42: ปรับค่า 91 กลุ่ม / 273 ภาพ, validation 30 กลุ่ม / 90 ภาพ, test 31 กลุ่ม / 93 ภาพ
- ภาพดัดแปลงของต้นฉบับเดียวกันไม่ข้ามชุด ไม่มีการใช้ label เป็นข้อมูลให้ detector
- ลอง 27 ชุดพารามิเตอร์บนชุดปรับค่า แล้วนำ 6 ชุดเข้า validation เลือกจากจำนวนภาพที่ IoU ≥ 0.5 มากที่สุด และใช้ mean IoU ตัดสินเมื่อเสมอ
- ตรึง `wide_fit80` ก่อนเปิดผล test ไม่ใช้ผล test ปรับค่าเพิ่มเติม การคงค่าปริยายเดิมเป็นการตัดสินใจใช้งานหลังประเมิน ไม่ใช่การปรับค่าด้วย test
- วัดกรอบสี่เหลี่ยมแนวแกนที่ครอบจุดมุมที่ detector เลือก เทียบกับ YOLO label; หากมีหลายป้าย ใช้ IoU สูงสุดกับป้ายใดป้ายหนึ่ง เพราะแอปคืนผลเพียงหนึ่งป้าย
- นับภาพที่ตรวจไม่พบเป็น IoU = 0 อัตราผ่านจึงใช้ภาพทั้งหมดเป็นตัวหาร ไม่ตัดภาพที่ตรวจไม่พบออก
- ผลนี้เป็นการวัดตำแหน่งของผลอันดับหนึ่ง ไม่ใช่ mAP, OCR accuracy หรือความแม่นยำของมุม/Homography เนื่องจาก label ไม่มีพิกัดมุมจริง

## ผลก่อนและหลัง

| ชุด | ภาพ | ค่าเดิม: IoU ≥ 0.5 | ค่าทดลอง: IoU ≥ 0.5 | mean IoU เดิม → ทดลอง |
| --- | ---: | ---: | ---: | ---: |
| ปรับค่า | 273 | 117 (42.9%) | 127 (46.5%) | 0.367 → 0.399 |
| Validation | 90 | 48 (53.3%) | 55 (61.1%) | 0.411 → 0.475 |
| Test ที่กันไว้ | 93 | 39 (41.9%) | 40 (43.0%) | 0.356 → 0.377 |

| รายละเอียดชุด test | ค่าเดิม | ค่าทดลอง |
| --- | ---: | ---: |
| ตรงกรอบที่ IoU ≥ 0.5 | 39 | 40 |
| คืนกรอบแต่ IoU < 0.5 | 27 | 48 |
| ไม่คืนกรอบ | 27 | 5 |
| ตรงกรอบ / ผลที่คืนทั้งหมด | 59.1% | 45.5% |
| ตรงกรอบที่เกณฑ์เข้มขึ้น IoU ≥ 0.75 | 14 | 14 |
| เวลาเฉลี่ยเฉพาะ detector ต่อภาพ | 30 ms | 50 ms |

เวลาวัดบนเครื่องนี้ด้วย worker เดียว ไม่รวมอ่าน/ถอดรหัสภาพและแสดงหน้าเว็บ; ไม่ใช่การรับรองเวลาใช้งานบนเครื่องอื่น

การผ่อนเกณฑ์มุมลดจำนวนภาพที่ไม่คืนกรอบ แต่ผลที่เพิ่มส่วนใหญ่ยังไม่ตรง label ชุด test จึงไม่ได้สนับสนุนว่าค่าทดลองดีกว่าค่าเดิมอย่างชัดเจน โดยเฉพาะเมื่อพิจารณากรอบที่แนบสนิทขึ้นที่ IoU ≥ 0.75

จากการตรวจตัวอย่าง บาง label ครอบบริเวณรอบป้ายกว้างกว่าหน้าป้ายจริง จึงมีกรณีที่ ROI มีป้ายอยู่ แต่ไม่ผ่าน IoU 0.5 เช่นตัวอย่างที่ 5 ในภาพเปรียบเทียบ คำว่า “คลาดเคลื่อน” ในตารางหมายถึงไม่ผ่านเกณฑ์เทียบ label ไม่ได้ยืนยันว่าทุกรูปไม่มีป้ายใน ROI

## พารามิเตอร์ที่ได้

| พารามิเตอร์ | ค่าเดิม (ภาพปานกลาง) | ทดลอง dataset v23 |
| --- | ---: | ---: |
| Gaussian blur | 7 | 3 |
| Canny ต่ำ / สูง | 35 / 110 | 20 / 80 |
| พื้นที่ขั้นต่ำอ้างอิง 1920 × 1080 | 150 | 150 |
| Aspect ratio ที่ยอมรับ | 0.9–4.5 | 0.6–4.5 |
| Aspect ratio ที่ได้คะแนนเต็ม | 1.4–2.5 | 1.0–2.5 |
| พื้นที่สูงสุดเทียบกับภาพ | 85% | 100% |
| ช่วงพื้นที่ที่คะแนนขนาดเต็ม* | 0.3–35% | 0.3–98% |
| สัดส่วนพื้นที่ contour กับสี่มุมขั้นต่ำ | 0.88 | 0.80 |
| Rectangularity สำหรับใช้ contour แรก | 0.70 | 0.65 |
| Solidity สำหรับใช้ contour แรก | 0.85 | 0.80 |

*คะแนนพื้นที่ยังคูณด้วยเกณฑ์พื้นที่ขั้นต่ำที่สเกลตามความละเอียดภาพ

น้ำหนักทั้ง 6 ด้านยังเป็น 10%, 15%, 15%, 10%, 15%, 35% ตามลำดับ Area, Aspect ratio, Rectangularity, Solidity, Approximation, Edge density; การเพิ่มน้ำหนัก Area ที่ทดลองไม่ทำให้ผลดีกว่า ชุดที่เลือกยังใช้คะแนนขั้นต่ำ 0.62 และ edge density ขั้นต่ำ 0.012 ไม่ได้ปรับ CLAHE / sharpening เพราะทำงานหลังตรวจจับและไม่เปลี่ยนกรอบที่นำมาวัด

## ใช้ในแอป

แอปเลือก **“ทดลอง dataset v23”** เป็นค่าเริ่มต้น อัปโหลดภาพแล้วกดค้นหาป้ายอัตโนมัติ จะใช้ทั้งค่า Blur/Canny และเกณฑ์คะแนน/มุมชุดที่ทดสอบ ไม่ใช่เพียงเลื่อน slider ให้ตรงกัน หากเลือก preset เดิมจะยังใช้เกณฑ์เดิม

รูปตัวอย่างใน [comparison.jpg](comparison.jpg) เลือกให้เห็นทั้งกรณีดีขึ้น แย่ลง และยังผิด ไม่ใช่ตัวอย่างสุ่มสำหรับสรุปความแม่นยำ สีเขียวคือ label สีส้มคือค่าเดิม สีฟ้าคือค่าทดลอง กล่องที่วาดเป็นกรอบสำหรับวัด IoU ไม่ใช่จุดมุมจริง

## ทำซ้ำและตรวจสอบ

```powershell
python scripts/evaluate_detector.py "C:\Users\Bhakin31\Downloads\License plate.v23-v4-8.yolov8.zip" --plan reports/plate_tuning/final_plan.json --output reports/plate_tuning/recheck --splits tune validation test --workers 1
python -m unittest discover -s tests -v
```

- `final_plan.json`: ค่าก่อน/หลังแบบครบทุกพารามิเตอร์
- `selected_config.json`: ค่าที่เลือกจาก validation และเหตุผลที่ยังเป็นตัวเลือกทดลอง
- `final/metrics.json`: ผลรวม พร้อม SHA-256 ของ ZIP และเวอร์ชัน runtime
- `final/split_manifest.json`: ชื่อภาพ กลุ่ม split และ label ที่ใช้
- `final/*_predictions.json`: กรอบที่เลือก คะแนน IoU และเวลารายภาพ
- `sweep_plan.json`, `refine_plan.json`, `area_plan.json`, `validation_plan.json`: แผนทดลองแต่ละรอบ; ผลรวมอยู่ในโฟลเดอร์ชื่อเดียวกัน

ชุดข้อมูลมีแต่ภาพที่มีป้าย จึงยังประเมินการคืนกรอบผิดบนภาพที่ไม่มีป้ายไม่ได้ ภาพดัดแปลงภายในกลุ่มยังสัมพันธ์กัน และการจัดกลุ่มอาศัยชื่อไฟล์ ไม่รับรองว่าภาพคล้ายกันที่ใช้ชื่อต่างกันไม่มีข้ามชุด ควรเก็บชุดทดสอบใหม่จากกล้องใช้งานจริง พร้อม label มุมทั้ง 4 หากจะวัด Homography โดยตรง
